BAB II​
PENGENALAN KONSEP BACKEND 

2.1. Definisi Backend 
Dalam pengembangan software, kamu pasti tidak asing dengan 

istilah Front-End dan Back-End. Kedua istilah ini merujuk pada dua sisi 
utama dari sistem aplikasi, dan sering kali menjadi titik awal bagi siapa 
pun yang ingin masuk ke dunia software development. Keduanya 
memiliki peran penting namun berbeda, dan pemahaman akan 
keduanya akan membantumu menentukan jalur karir yang ingin 
ditempuh. 

 
Front-End adalah bagian dari aplikasi yang langsung berinteraksi 

dengan pengguna. Ini mencakup tampilan visual, tata letak, dan 
bagaimana pengguna berinteraksi dengan fitur yang ada di halaman 
aplikasi. Seorang Front-End Developer bertanggung jawab untuk 
membangun antarmuka yang menarik, fungsional, dan user-friendly di 
berbagai platform seperti web, mobile, maupun desktop. 

 
Sebaliknya, Back-End adalah bagian dari sistem yang berjalan di 

balik layar. Komponen ini tidak terlihat oleh pengguna, tetapi sangat 
penting karena mengatur alur logika, menyimpan dan mengolah data, 
serta memastikan bahwa setiap permintaan dari Front-End ditangani 
dengan baik dan aman. Inilah yang membuat aplikasi berjalan 
sebagaimana mestinya. Orang yang bekerja di bidang ini disebut 
sebagai Back-End Developer, di mana mereka fokus pada hal-hal 
teknis seperti server, database, dan API untuk memastikan aplikasi 
berfungsi dengan optimal. 

 

2.2. Jobdesc Back-End Developer 
​ Seorang Back-End Developer memiliki tanggung jawab utama 
dalam membangun dan memelihara sistem server-side dari sebuah 
aplikasi. Peran ini berfokus pada pengelolaan data, implementasi logika 
bisnis, pengaturan autentikasi dan otorisasi pengguna, serta integrasi 
antara Front-End dan berbagai layanan eksternal. Back-End Developer 

​ ​                   
​ ​                   
​ ​ ​ 9 
 



 

juga bertanggung jawab terhadap keamanan sistem, performa 
aplikasi, dan efisiensi proses yang berjalan di balik layar. 

 
Tugas sehari-hari seorang Back-End Developer mencakup 

perancangan arsitektur sistem, pengembangan API untuk komunikasi 
antar bagian sistem, pemilihan dan konfigurasi database, serta 
penanganan error dan debugging. Selain itu, mereka juga harus 
memastikan bahwa sistem dapat menangani permintaan dalam skala 
besar, terutama untuk aplikasi dengan banyak pengguna. 

 
Dalam praktiknya, Back-End Developer bekerja dengan berbagai 

teknologi seperti bahasa pemrograman server-side (misalnya 
JavaScript dengan Node.js, Python, Java, atau GO), sistem manajemen 
database (seperti MySQL, PostgreSQL, atau MongoDB), serta framework 
atau library yang mendukung pengembangan yang efisien dan 
modular. Mereka juga menggunakan alat bantu seperti version control 
system (Git), alat dokumentasi API, dan sistem deployment untuk 
memastikan aplikasi berjalan dengan baik di lingkungan produksi. 

 
Kolaborasi juga menjadi bagian penting dari pekerjaan seorang 

Back-End Developer. Mereka harus mampu bekerja sama dengan 
Front-End Developer untuk memastikan integrasi fitur berjalan sesuai 
spesifikasi, serta berkoordinasi dengan tim DevOps, QA (Quality 
Assurance), dan Product Manager dalam siklus pengembangan 
software. 

 
Secara keseluruhan, Back-End Developer berperan penting 

dalam membangun pondasi teknis yang kuat, efisien, dan aman untuk 
mendukung performa dan stabilitas sebuah aplikasi 

 

2.3. Komponen Back-End 
Back-End terdiri dari sejumlah komponen utama yang saling 

terhubung dan bekerja sama untuk menjalankan fungsi sistem aplikasi 
secara keseluruhan. Komponen-komponen ini membentuk infrastruktur 
inti yang mendukung segala aktivitas yang terjadi di balik layar, mulai 
dari pemrosesan permintaan pengguna, pengelolaan data, hingga 
pengiriman respons kembali ke sisi Front-End. 
​ ​                   
​ ​                   
​ ​ ​ 10 
 



 

 
Tiga komponen fundamental dalam sistem Back-End adalah 

server, API, dan database. Server bertindak sebagai pusat kendali yang 
memproses permintaan dari client. API menjadi jembatan komunikasi 
antara sistem dan antarmuka pengguna. Sementara itu, database 
menyimpan dan menyediakan data yang dibutuhkan oleh aplikasi 
secara terstruktur dan aman. 

 
Ketiga komponen ini saling melengkapi dan berperan penting 

dalam menjaga performa, keandalan, serta skalabilitas aplikasi, baik 
dalam skala kecil maupun besar. 

​  
2.3.1. Server 
 
Server adalah komponen utama dalam sistem Back-End yang 
bertugas menerima, memproses, dan merespons permintaan 
dari client (biasanya Front-End atau aplikasi lain). Server 
bertindak sebagai pusat kendali logika aplikasi dan bertanggung 
jawab untuk menjalankan berbagai instruksi berdasarkan 
permintaan pengguna, seperti menampilkan data, memproses 
input, atau melakukan fungsi tertentu di sistem. 
 
Dalam konteks arsitektur client-server, client mengirimkan 
request (permintaan) ke server, dan server memberikan response 
(respons) sesuai dengan logika yang telah ditentukan. Server 
tidak boleh diakses langsung oleh end-user, melainkan hanya 
merespons permintaan yang telah dirancang secara terstruktur 
dan melalui jalur komunikasi yang aman, biasanya melalui API. 
 
Server tidak merujuk pada perangkat keras secara spesifik, tetapi 
lebih kepada sistem atau software yang menyediakan layanan 
tertentu. Sebuah komputer fisik atau virtual bisa menjalankan 
berbagai jenis server tergantung layanan yang disediakan. 
Beberapa jenis server yang umum dalam pengembangan 
aplikasi antara lain: 
 
●​ Web Server: Menyediakan layanan akses ke aplikasi 
berbasis web melalui protokol HTTP atau HTTPS. 

​ ​                   
​ ​                   
​ ​ ​ 11 
 



 

●​ Application Server: Menjalankan logika aplikasi dan 
mengatur komunikasi antara web server dan database. 
●​ Database Server: Menyediakan akses terhadap sistem 
penyimpanan data yang terstruktur. 
●​ File Server: Menyediakan layanan penyimpanan dan 
distribusi file. 
●​ DNS Server: Mengelola penerjemahan domain ke alamat IP 
yang dapat dikenali jaringan. 
 
Dalam pengembangan back-end modern, server sering 
dirancang sebagai layanan RESTful API atau RPC yang berjalan 
terus-menerus (long-running service) di atas protokol HTTP. 
Server ini dapat dikembangkan secara modular dan ringan 
menggunakan package seperti net/http atau framework pihak 
ketiga seperti gin, echo, atau fiber. 
 
Server juga bertanggung jawab untuk menangani aspek-aspek 
teknis lain seperti autentikasi, logging, validasi input, pengaturan 
middleware, dan pengelolaan session. Keandalan dan efisiensi 
server sangat menentukan seberapa cepat dan stabil sebuah 
aplikasi dapat memberikan layanan kepada penggunanya. 

 
2.3.2. API 
​
API (Application Programming Interface) adalah antarmuka yang 
memungkinkan satu sistem berkomunikasi dengan sistem lain 
melalui format dan aturan yang telah ditentukan. Dalam 
pengembangan Back-End, API digunakan sebagai penghubung 
utama antara server dan client, sehingga Front-End dapat 
mengirim permintaan data atau instruksi ke Back-End tanpa 
perlu mengetahui bagaimana sistem internal dijalankan. 
 
API menyediakan sekumpulan endpoint (alamat dan metode 
akses) yang dapat digunakan oleh client untuk melakukan 
operasi tertentu, seperti mengambil daftar data, mengirim input, 
memperbarui informasi, atau menghapus entri. Proses ini 
umumnya mengikuti protokol komunikasi HTTP dan 

​ ​                   
​ ​                   
​ ​ ​ 12 
 



 

menggunakan struktur data seperti JSON dalam request maupun 
response. 
 
Salah satu bentuk API yang paling umum digunakan saat ini 
adalah RESTful API, di mana operasi-operasi utama CRUD 
(Create, Read, Update, Delete) dipetakan pada metode HTTP 
seperti POST, GET, PUT/PATCH, dan DELETE. Dengan REST, sistem 
menjadi lebih modular, mudah diintegrasikan, dan scalable. 
 
API juga menjadi titik krusial untuk penerapan berbagai fitur 
penting dalam aplikasi, seperti: 
 
●​ Autentikasi dan otorisasi: memastikan hanya pengguna 
yang berwenang dapat mengakses data atau menjalankan 
tindakan tertentu. 
●​ Validasi input: menyaring dan memverifikasi data yang 
dikirim dari client sebelum diproses oleh server. 
●​ Manajemen error: memberikan pesan responsif dan jelas 
saat terjadi kesalahan pada sisi client maupun server. 
 
API adalah titik masuk utama ke dalam sistem Back-End. Oleh 
karena itu, desain yang konsisten, aman, dan terdokumentasi 
dengan baik menjadi kunci dalam membangun layanan 
Back-End yang handal. 

 
2.3.3. Database 
 
Database adalah komponen penting dalam pengembangan 
back-end yang berfungsi sebagai tempat penyimpanan seluruh 
data yang digunakan oleh aplikasi. Di sinilah informasi seperti 
data pengguna, produk, transaksi, dan konten lainnya disimpan 
secara terstruktur dan dapat diakses kembali kapan saja sesuai 
kebutuhan. 
 
Database dibedakan menjadi dua jenis utama berdasarkan 
struktur datanya: 
 

​ ​                   
​ ​                   
​ ​ ​ 13 
 



 

●​ Relasional (SQL): Menggunakan tabel dengan kolom dan 
baris untuk menyimpan data, serta menerapkan relasi antar 
tabel. Contoh sistem manajemen database relasional (RDBMS) 
antara lain MySQL, PostgreSQL, dan SQLite. Sistem ini cocok untuk 
aplikasi yang memerlukan konsistensi data tinggi dan struktur 
data yang jelas. 
●​ Non-relasional (NoSQL): Menyimpan data dalam format 
non-tabel seperti dokumen, key-value, atau grafik. Contoh dari 
database NoSQL adalah MongoDB dan Redis. Jenis ini lebih 
fleksibel dan cocok untuk data yang dinamis atau tidak memiliki 
skema tetap. 
 
Dalam konteks back-end, interaksi dengan database dilakukan 
melalui perintah-perintah seperti SELECT, INSERT, UPDATE, dan 
DELETE. Perintah ini memungkinkan pengambilan, penambahan, 
perubahan, maupun penghapusan data dalam jumlah besar 
dengan efisien. Untuk menghindari duplikasi dan memastikan 
integritas data, developer biasanya juga merancang struktur 
database dengan memperhatikan normalisasi, relasi antar tabel, 
serta indeks. 
 
Peran database tidak hanya sebatas penyimpanan. Ia juga 
memiliki tanggung jawab penting dalam keamanan data, 
efisiensi akses, serta mendukung logika bisnis yang kompleks 
melalui penggunaan query dan prosedur tersimpan. Dalam 
sistem yang berskala besar, optimisasi query dan manajemen 
beban database menjadi faktor krusial yang menentukan 
performa aplikasi secara keseluruhan.

3.3. Go Routines 
Goroutine secara konsep mirip seperti thread, meskipun 

sebenarnya berbeda. Sebuah native thread bisa berisikan sangat 
banyak goroutine. Mungkin lebih pas kalau goroutine disebut sebagai 
mini thread. Goroutine sangat ringan, hanya dibutuhkan sekitar 2kB 
memori saja untuk satu buah goroutine. Eksekusi goroutine bersifat 
asynchronous, menjadikannya tidak saling tunggu dengan goroutine 
lain. 

 
Karena goroutine sangat ringan, maka eksekusi banyak 

goroutine bukan masalah. Akan tetapi jika jumlah goroutine sangat 
banyak sekali (contoh 1 juta goroutine dijalankan pada komputer 
dengan RAM terbatas), memang proses akan jauh lebih cepat selesai, 
tapi memory/RAM pasti bengkak. Selain itu, dalam pengaplikasiannya 
jangan hanya terpaku pada size goroutine yang kecil tersebut, tapi 
pertimbangkan juga kode/proses/logic yang dibuat di dalam 
goroutine itu sekompleks apa, karena hal tersebut sangat berpengaruh 
dengan konsumsi resource hardware. 

Goroutine merupakan salah satu bagian paling penting dalam 
concurrent programming di Go. Salah satu yang membuat goroutine 
sangat istimewa adalah eksekusi-nya dijalankan di multi core 
processor. Kita bisa tentukan berapa banyak core yang aktif, semakin 
banyak akan semakin cepat.  

Untuk menerapkan goroutine, proses yang akan dieksekusi 
sebagai goroutine harus dibungkus ke dalam sebuah fungsi, ini

3.4.1. MVC 

A. Controller 
Air traffic controllers adalah orang-orang yang 

memberi tahu setiap pesawat di bandara tentang ke mana 
harus terbang, kapan harus mendarat, dan di landasan 
mana harus mendarat. Mereka tidak menerbangkan 
pesawat secara langsung, tetapi bertugas memberikan 
arahan agar bandara bisa berjalan dengan lancar. 

Controllers dalam MVC sangat mirip dengan air 
traffic controllers. Mereka tidak bertanggung jawab 
langsung untuk menulis ke database atau membuat HTML 
response, tetapi mereka mengarahkan data yang masuk ke 
model, view, dan package lain yang sesuai untuk 
menyelesaikan permintaan.

B. Models 
Models adalah bagian dari MVC, dan tanggung 

jawab utamanya adalah berinteraksi dengan data milik 
aplikasi kamu. Ini biasanya berarti berkomunikasi dengan 
database, tapi bisa juga berarti berinteraksi dengan data 
yang berasal dari layanan atau API lain. Bisa juga termasuk 
proses validasi atau normalisasi data. 

Contoh singkat — sebagian besar web application 
biasanya memiliki konsep user yang mendaftar dan 
berinteraksi dengan aplikasi tersebut. Dalam aplikasi 
berbasis MVC, kita mungkin membuat tipe User struct {...} di 
dalam package models yang merepresentasikan user yang 
disimpan di dalam database. Lalu kita bisa membuat kode 
untuk membantu memvalidasi apakah user tersebut valid, 
serta kode tambahan untuk membuat, memperbarui, atau 
mencari data user di database. 

Satu hal penting yang ingin saya tekankan di sini 
adalah bahwa saya menganggap package models 
mencakup seluruh interaksi dengan database. 

C. Routes 
​ ​ Dalam arsitektur MVC 
(Model-View-Controller), folder routes berfungsi untuk 
mendefinisikan rute (routes) atau jalur-jalur URL yang 
akan diproses oleh aplikasi web. Folder ini biasanya berisi 
kode yang menghubungkan request HTTP (seperti GET, 
POST, PUT, DELETE) ke controller yang sesuai. 

D. Database 
Sebaiknya lapisan database di-abstract agar jika 

suatu saat kamu perlu melakukan perubahan, kamu tidak 
perlu mencari-cari query di dalam business logic. Semua 
query disimpan di dalam folder models.

Go mengadopsi dua jenis penulisan variabel, yaitu yang 

dituliskan tipe data-nya dan yang tidak. Kedua cara tersebut valid dan 
tujuannya sama yaitu untuk deklarasi variabel, perbedaannya hanya 
pada cara penulisannya saja. 

3.5.1. Deklarasi Variabel Beserta Tipe Data  
Go memiliki aturan cukup ketat dalam hal penulisan 

variabel. Ketika deklarasi, tipe data yg digunakan harus dituliskan 
juga. Istilah dari metode deklarasi variabel ini adalah manifest 
typing. Berikut adalah contoh cara pembuatan variabel yang tipe 
datanya harus ditulis. Silakan tulis pada project baru atau pada

3.5.2. Deklarasi Variabel Menggunakan Keyword var 

Pada kode di atas bisa dilihat bagaimana sebuah variabel 
dideklarasikan dan diisi nilainya. Keyword var digunakan untuk 
membuat variabel baru. Skema penggunaan keyword var: 
var <nama-variable> <tipe-data> 
var <nama-variable> <tipe-data> = <nilai> 
Contoh: 
var firstName string = "john" 
 
var lastName string 
Nilai variabel bisa di-isi langsung pada saat deklarasi variabel. 

●​ Penggunaan Fungsi fmt.Printf() 

Fungsi ini digunakan untuk menampilkan output

Contoh lain, ketiga baris kode berikut ini akan menghasilkan

3.5.3.​ Deklarasi Variabel Tanpa Tipe Data 

Selain manifest typing, Go juga mengadopsi konsep type 
inference, yaitu metode deklarasi variabel yang tipe data-nya 
diketahui secara otomatis dari data/nilai variabel. Cara ini 
kontradiktif jika dibandingkan dengan cara pertama. Dengan 
metode jenis ini, keyword var dan tipe data tidak perlu ditulis. 

var firstName string = "john"​
lastName := "wick"​
fmt.Printf("halo %s %s!\n", firstName, lastName) 

Variabel lastName dideklarasikan dengan menggunakan 
metode type inference. Penandanya tipe data tidak dituliskan 
pada saat deklarasi. Pada penggunaan metode ini, operand = 
harus diganti dengan := dan keyword var dihilangkan. 

Tipe data lastName secara otomatis akan ditentukan 
menyesuaikan value atau nilai-nya. Jika nilainya adalah berupa 
string maka tipe data variabel adalah string. Pada contoh di atas, 
nilainya adalah string "wick". Diperbolehkan untuk tetap 

​ ​                   
​ ​                   
​ ​ ​ 29 
 



 

menggunakan keyword var pada saat deklarasi meskipun tanpa 
menuliskan tipe data, dengan ketentuan tidak menggunakan 
tanda :=, melainkan tetap menggunakan =. 

// menggunakan var, tanpa tipe data, menggunakan perantara 
"="​
var firstName = "john"​
​
// tanpa var, tanpa tipe data, menggunakan perantara ":="​
lastName := "wick" 

Tanda := hanya digunakan sekali di awal pada saat deklarasi. 
Untuk assignment nilai selanjutnya harus menggunakan tanda =, 
contoh: 
lastName := "wick" 
lastName = "ethan" 
lastName = "bourne" 
Deklarasi menggunakan := hanya bisa dilakukan di dalam blok 
fungsi, misalnya dalam blok fungsi main() 

3.5.4.​Deklarasi Multi Variabel 

Go mendukung metode deklarasi banyak variabel secara 
bersamaan, caranya dengan menuliskan variabel-variabel-nya

diperbolehkan secara bersamaan.

(,). 
var fourth, fifth, sixth string = "empat", "lima", "enam" 
 
Kalau ingin lebih ringkas: 
seventh, eight, ninth := "tujuh", "delapan", "sembilan"

3.5.5. Variabel Underscore _ 
Go memiliki aturan unik yang jarang dimiliki bahasa lain, 

yaitu tidak boleh ada satupun variabel yang menganggur. 
Artinya, semua variabel yang dideklarasikan harus digunakan. 
Jika ada variabel yang tidak digunakan tapi dideklarasikan, error 
akan muncul pada saat kompilasi dan program tidak akan bisa 
di-run. 

 

Underscore (_) adalah reserved variable yang bisa 
dimanfaatkan untuk menampung nilai yang tidak dipakai. Bisa 
dibilang variabel ini merupakan keranjang sampah.

_ = "Golang itu mudah" 
name, _ := "john", "wick" 

Pada contoh di atas, variabel name akan berisikan text 
john, sedang nilai wick ditampung oleh variabel underscore, 
menandakan bahwa nilai tersebut tidak akan digunakan. 

Variabel underscore adalah predefined, jadi tidak perlu 
menggunakan := untuk pengisian nilai, cukup dengan = saja. 
Namun khusus untuk pengisian nilai multivariabel yang dilakukan 
dengan metode type inference, boleh di dalamnya terdapat 
variabel underscore. 

Biasanya variabel underscore sering dimanfaatkan untuk 
menampung nilai balik fungsi yang tidak digunakan. 

Perlu diketahui, bahwa isi variabel underscore tidak dapat 
ditampilkan. Data yang sudah masuk variabel tersebut akan 
hilang. Ibarat variable underscore ini seperti blackhole, objek 
apapun yang masuk ke dalamnya, akan terjebak selamanya 
di-dalam singularity dan tidak akan bisa keluar .

3.10​ Fungsi  
Dalam konteks pemrograman, fungsi adalah sekumpulan blok

Sebenarnya kita sudah mengimplementasikan fungsi pada

membungkus blok kode. 

Parameter merupakan variabel yang menempel di fungsi

Parameter sifatnya opsional, suatu fungsi bisa tidak memiliki

3.11​ Pointer 
Pointer adalah reference atau alamat memori. Variabel pointer 

berarti variabel yang berisi alamat memori suatu nilai. Sebagai contoh 
sebuah variabel bertipe integer memiliki nilai 4, maka yang dimaksud 
pointer adalah alamat memori di mana nilai 4 disimpan, bukan nilai 4 
itu sendiri. 

Variabel-variabel yang memiliki reference atau alamat pointer 
yang sama, saling berhubungan satu sama lain dan nilainya pasti 
sama. Ketika ada perubahan nilai, maka akan memberikan efek 
kepada variabel lain (yang referensinya sama) yaitu nilainya ikut 
berubah. 

3.11.1. Penerapan Pointer 

Variabel bertipe pointer ditandai dengan adanya tanda 
asterisk (*) tepat sebelum penulisan tipe data ketika deklarasi. 
var number *int 
var name *string 

Nilai default variabel pointer adalah nil (kosong). Variabel 
pointer tidak bisa menampung nilai yang bukan pointer, dan 
sebaliknya variabel biasa tidak bisa menampung nilai pointer. 

Ada dua hal penting yang perlu diketahui mengenai pointer: 

●​ Variabel biasa bisa diambil nilai pointernya, caranya 
dengan menambahkan tanda ampersand (&) tepat 
sebelum nama variabel. Metode ini disebut dengan 
referencing. 

●​ Dan sebaliknya, nilai asli variabel pointer juga bisa diambil, 
dengan cara menambahkan tanda asterisk (*) tepat 
sebelum nama variabel. Metode ini disebut dengan 
dereferencing. 

var numberA int = 4​
var numberB *int = &numberA​
​
fmt.Println("numberA (value)   :", numberA)  // 4​
fmt.Println("numberA (address) :", &numberA) // 0xc20800a220​
​

​ ​                   
​ ​                   
​ ​ ​ 57 
 



 

fmt.Println("numberB (value)   :", *numberB) // 4​
fmt.Println("numberB (address) :", numberB)  // 0xc20800a220 

Variabel numberB dideklarasikan bertipe pointer int dengan 
nilai awal adalah referensi variabel numberA (bisa dilihat pada 
kode &numberA). Dengan ini, variabel numberA dan numberB 
menampung data dengan referensi alamat memori yang sama. 

 

Variabel pointer jika di-print akan menghasilkan string 
alamat memori (dalam notasi heksadesimal), contohnya seperti 
numberB yang diprint menghasilkan 0xc20800a220. 

Nilai asli sebuah variabel pointer bisa didapatkan dengan 
cara di-dereference terlebih dahulu (bisa dilihat pada kode 
*numberB). 

3.11.2. Efek Perubahan Nilai Pointer 

Ketika salah satu variabel pointer di ubah nilainya, sedang 
ada variabel lain yang memiliki referensi memori yang sama, 
maka nilai variabel lain tersebut juga akan berubah. 

Variabel numberA dan numberB memiliki referensi memori 
yang sama. Perubahan pada salah satu nilai variabel tersebut 
akan memberikan efek pada variabel lainnya. Pada contoh di 
atas, numberA nilainya di ubah menjadi 5. membuat nilai asli 
variabel numberB ikut berubah menjadi 5.

3.11.3. Parameter Pointer 

Parameter bisa juga dirancang sebagai pointer. Cara 
penerapannya kurang lebih sama, dengan cara mendeklarasikan 
parameter sebagai pointer.

    var number = 4​
    fmt.Println("before :", number) // 4​

Fungsi change() memiliki 2 parameter, yaitu original yang

Nilai variabel number berubah menjadi 10 karena 
perubahan yang terjadi di dalam fungsi change adalah pada

3.12.1. Struct 

Go tidak mengadopsi konsep class seperti pada beberapa

Struct adalah kumpulan definisi variabel (atau property)

Dari sebuah struct, kita bisa buat variabel baru, yang

chapter ini. 

Dengan memanfaatkan struct, penyimpanan data yang 
sifatnya kolektif menjadi lebih mudah, lebih rapi, dan mudah 
untuk dikelola.

3.12.2. Interface 

Interface adalah definisi suatu kumpulan method yang 
tidak memiliki isi, jadi hanya definisi header/schema-nya saja.

REST API 

4.1.​ Definisi REST API 

REST API (atau lebih lengkapnya Representational State Transfer 
API) merupakan salah satu komponen inti dalam pengembangan 
backend aplikasi modern. REST API memungkinkan komunikasi antara 
client (seperti aplikasi web atau mobile) dengan server backend, 
biasanya menggunakan protokol HTTP. Konsep REST API sangat cocok 
diterapkan di banyak skenario seperti pengiriman data dinamis, 
sinkronisasi antar sistem, hingga layanan pihak ketiga yang bersifat 
publik. 

Saat kamu membuka aplikasi cuaca dan langsung melihat 
prediksi hujan, atau scroll Instagram dan melihat feed terbaru, 
sebenarnya kamu sedang berinteraksi dengan REST API di balik layar. 
REST API membuat pertukaran data menjadi cepat, efisien, dan 
terstruktur. 

REST API merupakan implementasi dari arsitektur REST yang 
diperkenalkan oleh Roy Fielding. REST adalah gaya arsitektur komunikasi 
berbasis protokol HTTP yang menekankan prinsip sederhana seperti 
statelessness, penggunaan resource URI, serta format pertukaran data 
yang ringan seperti JSON. 

Dalam praktiknya, REST API menggunakan berbagai HTTP method 
seperti GET, POST, PUT, dan DELETE untuk mengakses atau memanipulasi 
resource di server. Resource ini biasanya direpresentasikan dalam 
bentuk JSON karena mudah dibaca manusia dan juga ringan untuk 
dikirimkan. 

Secara sederhana, analogi REST API bisa dibayangkan seperti 
saat kita memesan makanan di restoran. Kita memesan ke pelayan 
(client membuat request), pesanan disampaikan ke dapur (server 
memproses permintaan), lalu makanan disajikan ke meja kita (server 
mengirimkan response).

4.2. Struktur Umum REST API 

4.2.1. Request 
Request adalah proses ketika user mengirimkan informasi 

atau permintaan ke server. Beberapa jenis request (HTTP 
methods) yang umum digunakan yaitu GET, POST, PUT, PATCH, 
DELETE. 

 
Berikut adalah struktur dari request :  

 
https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Messages 

 
1.​ Request Targets 

Ada beberapa cara untuk menggambarkan request 
target dalam HTTP, tetapi yang paling umum digunakan 
adalah bentuk origin form. Pada origin form, server 
penerima akan menggabungkan absolute path dengan 
informasi yang ada di header Host. Jika diperlukan, sebuah 
query string dapat ditambahkan ke path untuk 
menyertakan informasi tambahan dalam format 
key=value. Bentuk ini biasanya digunakan bersama metode 
GET, POST, HEAD, dan OPTIONS.

2.​ Request Headers 
Request Headers (background berwarna pink) 

adalah metadata yang dikirim dalam request. Request 
Headers digunakan untuk memberikan konteks tambahan 
pada sebuah request atau menambahkan logika khusus 
mengenai bagaimana request tersebut harus diperlakukan 
oleh server 

Sementara itu, representation headers (background 
berwarna hijau) dikirim dalam request jika pesan tersebut 
memiliki body. Header ini berfungsi untuk menjelaskan 
bentuk asli dari data message beserta encoding yang 
diterapkan, sehingga penerima dapat memahami 
bagaimana cara merekonstruksi resource. 

3.​ Request Body 
Body pada request adalah bagian dari request yang 

berisi data atau informasi yang dikirimkan ke server. Bagian 
ini biasanya digunakan ketika kita ingin menambahkan, 
memperbarui, atau mengubah data, sehingga hanya 
metode seperti PATCH, POST, dan PUT yang umumnya 
memiliki body. 

4.2.2. Response 

Response adalah pesan HTTP yang dikirim server sebagai 
balasan dari sebuah request. Melalui response ini, client diberi 
tahu bagaimana hasil dari permintaan yang dikirimkan — 
apakah berhasil, gagal, atau ada kondisi khusus yang perlu 
ditangani.

1.​ Response Headers 

Sama seperti request headers, response juga 
memiliki banyak jenis header dan biasanya dikelompokkan 
berdasarkan fungsinya. Response headers (background 
berwarna pink) digunakan untuk memberikan konteks 
tambahan mengenai pesan atau menambahkan logika 
tentang bagaimana client sebaiknya melakukan 
permintaan berikutnya.  

Selain itu ada representation headers (background 
berwarna hijau), yang digunakan ketika response memiliki 
body. Header ini menjelaskan bentuk data pesan serta 
encoding apa yang diterapkan. Contohnya, resource yang 
sama bisa diformat dalam jenis media tertentu seperti XML 
atau JSON, disesuaikan ke bahasa atau wilayah tertentu, 
atau dikompres agar lebih efisien saat dikirim. 

2.​ Response Body 

Sebuah response body biasanya disertakan dalam 
kebanyakan pesan ketika server memberikan balasan 
kepada client. Jika permintaan berhasil, body ini berisi data 
yang diminta client, misalnya hasil dari sebuah GET request.

4.5. Simple HTTP Server 

Contoh sederhana HTTP server menggunakan Go dan net/http :

    "fmt"​

}​

​
    fmt.Println("Server berjalan di http://localhost:8080")​

}​

●​ http.HandleFunc("/"): menghubungkan path root ke fungsi

●​ http.ListenAndServe(":8080", nil): menjalankan server di port 8080

5.1.1. Pengertian Context pada Go 
Context adalah package bawaan dalam Go yang 

digunakan untuk mengelola proses komunikasi antar goroutine, 
terutama dalam aplikasi HTTP. Context akan menyediakan 
mekanisme untuk mengontrol lifecycle, cancellation

eksplisit. 

Context menjadi sangat penting dalam aplikasi server-side 
agar proses tidak berjalan terus-menerus tanpa kontrol, 
khususnya ketika klien memutus koneksi atau terjadi error 
internal.

5.3.1. Binding Data 

Binding adalah proses mengikat data dari request (query,

membuat penanganan data input menjadi lebih efisien,

terstruktur, dan aman, tanpa parsing manual. Gin menyediakan

a.​ Must Bind 
Metode : Bind, BindJSON, BindXML, BindQuery, BindYAML.

r.GET("/user/:name", func(c *gin.Context) {​
    name := c.Param("name")​
    c.String(200, "Hello %s", name)​
}) 

Dalam contoh, rute /user/:name akan mencocokkan permintaan 
apapun dengan rute yang dimulai dengan /user/ diikuti oleh 
parameter name. Misal mengakses /user/BST, respons : Hello BST.

​ ​

b.​ Query 
Parameter kueri digunakan untuk memberikan informasi 
tambahan ke server dalam bentuk pasangan key-value. 
Pasangan ini dapat diakses menggunakan Query(), metode objek 
Context. Contoh : 

r.GET("/users", func(c *gin.Context) {​
    name := c.Query("name")​
    age := c.Query("age")​
    // Handle request with name and age query 
parameters​
}) 

Pada contoh, rute /users akan menyocokkan permintaan apapun 
dengan jalur yang dimulai dengan /users serta menyertakan 
parameter kueri name dan age.

route​

route​

5.5. Middleware (Built in & Custom) 

5.5.1. Pengertian Middleware 
Middleware adalah fungsi yang dijalankan sebelum atau 

sesudah handler utama dipanggil dalam proses permintaan 
(request). Middleware biasanya digunakan untuk : 
●​ Logging (mencatat request) 
●​ Authentication/Authorization 
●​ Validasi data 
●​ Menangani panic 
●​ Manipulasi header/respons 
Dalam Gin, middleware berbentuk fungsi seperti berikut : 

func(c *gin.Context) 
Fungsi ini dapat melanjutkan eksekusi ke handler berikutnya 
dengan c.Next() atau menghentikan eksekusi dengan c.Abort(). 
Middleware juga dapat membaca menggunakan c.Request() 
dan memodifikasi menggunakan c.Writer().

5.5.2. Built-in Middleware 
Gin menyediakan beberapa middleware bawaan (built-in) 

yang siap digunakan : 
a.​ gin.Logger() 
●​ Mencetak log dari setiap request HTTP yang masuk. 
●​ Log berisi informasi seperti path, status, waktu eksekusi, dsb. 
●​ Cocok digunakan saat development atau debugging. 

router:=gin.New()​
router.Use(gin.Logger()) 

 
b.​ gin.Recovery() 
●​ Menangkap panic yang terjadi dalam handler, lalu 
mengembalikan HTTP 500. 
●​ Mencegah crash dan menampilkan log error yang jelas.

5.5.3. Custom Middleware 

Custom middleware memungkinkan kita membuat logika 
khusus sesuai kebutuhan aplikasi. Contoh :  

func LoggerMiddleware() gin.HandlerFunc {​
    return func(c *gin.Context) {​
        t := time.Now()​
        path := c.Request.URL.Path​
​
        // Lanjut ke handler​
        c.Next()​
​
        latency := time.Since(t)​
        status := c.Writer.Status()​
        fmt.Printf("Path: %s | Status: %d | Durasi: 
%v\n", path, status, latency)​
    }​
}

Middleware di atas digunakan untuk mencatat informasi setiap 
permintaan (request) yang masuk. Fungsi ini mencatat waktu 
saat request diterima, melanjutkan proses ke handler berikutnya 
menggunakan c.Next(), lalu menghitung durasi pemrosesan 
(latency) setelah handler selesai. Informasi yang dicatat meliputi 
path yang diakses, status HTTP yang dikembalikan, dan lama 
waktu proses. Middleware ini berguna untuk melakukan logging 
kinerja dan memantau performa server secara manual.

BAB VI​
DATABASE & GORM 

6.1. Jenis-jenis Database (Relasional dan Non Relasional) 

Secara umum, database dibagi menjadi dua jenis utama, yaitu 
database relasional dan database non relasional (NoSQL). 
 

a.​ Database Relasional 
Database relasional menyimpan data dalam bentuk tabel dan 

menggunakan SQL (Structured Query Language) untuk mengelola 
data. Setiap tabel memiliki baris dan kolom yang terstruktur dengan 
relasi antar tabel. 

Contoh: MySQL, PostgreSQL, SQLite, SQL Server​
 

b.​ Database Non Relasional (NoSQL) 
Database non relasional menyimpan data dalam format yang 

lebih fleksibel, seperti dokumen, key-value, graf, atau kolom lebar. 
Biasanya tidak menggunakan skema tetap dan tidak menggunakan 
SQL. 

Contoh: MongoDB (document-based), Redis (key-value), 
Cassandra (wide-column), Neo4j (graph-based). 

6.2. Definisi ORM 

ORM (Object-Relational Mapping) dalam konteks Go adalah 
sebuah teknik yang memungkinkan pengembang untuk berinteraksi 
dengan database menggunakan objek-objek dalam bahasa 
pemrograman, tanpa harus menulis query SQL secara langsung. Dalam 
Go, ORM seperti GORM (Go ORM) menyediakan berbagai fungsi untuk 
mempermudah operasi database seperti membuat, membaca, 
memperbarui, dan menghapus data (CRUD) serta mengelola relasi 
antar tabel.  

​ ​                   
​ ​                   
​ ​ ​ 109 
 



 

6.3. Declaring model  

Model didefinisikan menggunakan struct biasa. Struct ini dapat 
berisi field dengan tipe dasar Go, pointer atau alias dari tipe itu, atau 
bahkan tipe custom, selama tetap mengimplementasikan Scanner dan 
Valuer interface dari database/sql package. Perhatikan contoh model 
User dibawah ini: 

 
type User struct {​

  ID           uint           // Standard field for the primary key​
  Name         string         // A regular string field​
  Email        *string        // A pointer to a string, allowing for null values​
  Age          uint8          // An unsigned 8-bit integer​
  Birthday     *time.Time     // A pointer to time.Time, can be null​
  MemberNumber sql.NullString // Uses sql.NullString to handle nullable strings​
  ActivatedAt  sql.NullTime   // Uses sql.NullTime for nullable time fields​
  CreatedAt    time.Time      // Automatically managed by GORM for creation time​
  UpdatedAt    time.Time      // Automatically managed by GORM for update time​
  ignored      string         // fields that aren't exported are ignored​
} 

 

Dalam model ini: 

1.​ Tipe data dasar seperti uint, string, dan uint8 digunakan 
secara langsung. 

2.​ Sebuah pointer ke tipe seperti *string dan *time.Time 
mengindikasikan bidang yang dapat bernilai null. 

3.​ sql.NullString dan sql.NullTime dari package database/sql 
digunakan untuk bidang yang dapat bernilai null dengan 
kontrol yang lebih luas. 

4.​ CreatedAt dan UpdatedAt adalah bidang khusus yang 
secara otomatis diisi oleh GORM dengan waktu saat ini 
ketika record dibuat atau diperbarui. 

5.​ Ignore adalah field yang berisi hal yang ingin diabaikan 
(tidak dimasukkan) 

​ ​                   
​ ​                   
​ ​ ​ 110 
 



 

6.3.1. Convention 
1.​ Primary Key: GORM menggunakan field bernama ID 

sebagai primary key default untuk setiap model. 
type User struct {​
  ID   string // field named `ID` used as a primary 
field by default​
  Name string​
} 

Namun, bisa juga menggunakan nama selain ‘ID’ dengan 
cara menambahkan tag “primaryKey” seperti berikut 

// Set field `UUID` as primary field​
type Animal struct {​
  ID     int64​
  UUID   string `gorm:"primaryKey"`​
  Name   string​
  Age    int64​
} 

2.​ Table Names: Secara default, GORM akan mengubah nama 
dari sebuah struct menjadi style  snake_case. Sebagai 
contoh nama struct User akan menjadi users di dalam 
database, dan nama seperti  GormUserName akan menjadi  
gorm_user_names. Namun, hal ini juga bisa dilakukan 
secara manual jika kita ingin dengan menggunakan Tabler 
interface, seperti berikut 

type Tabler interface {​
  TableName() string​
}​
​
// TableName overrides the table name used by User to 
`profiles`​
func (User) TableName() string {​
  return "profiles"​
} 

​ ​                   
​ ​                   
​ ​ ​ 111 
 



 

TableName ini tidak mengizinkan pengubahan nama 
secara dynamic, hasilnya hanya berupa cache yang akan 
digunakan di masa depan, jika ingin dynamic bisa 
menggunakan Scope. GORM mengizinkan user untuk 
membuat nama custom menggunakan NamingStrategy, 
yang digunakan seperti TableName, ColumnName, 
JoinTableName, RelationshipFKName, CheckerName, 
IndexName. 

3.​ Column Names: GORM juga secara otomatis mengubah 
nama field menjadi style snake_case untuk nama kolom di 
database. Kita bisa melakukan kustomisasi nama 
menggunakan NamingStrategy maupun menggunakan 
tag seperti dibawah ini 

type Animal struct { 
  AnimalID int64     `gorm:"column:beast_id"`         
  Birthday time.Time `gorm:"column:day_of_the_beast"`  
  Age      int64     `gorm:"column:age_of_the_beast"`  
} 

4.​ Timestamp Fields: GORM menggunakan field bernama 
CreatedAt dan UpdatedAt untuk mendeteksi secara 
otomatis kapan terjadinya creation dan update di dalam 
records. Timestamps otomatis ini juga dapat dimatikan jika 
kita menginginkannya menggunakan tag seperti dibawah 
ini  

type User struct { 
  CreatedAt time.Time `gorm:"autoCreateTime:false"` 
} 

Syntax diatas juga berlaku untuk UpdateAt. Dengan 
mengikuti konvensi ini kita dapat mengurangi jumlah 
konfigurasi atau kode yang harus kita buat.

​ ​                   
​ ​ ​ 112 
 



 

6.3.2. gorm.Model 

GORM menyediakan sebuah struktur bawaan bernama 
gorm.Model yang sudah mencakup field (kolom) yang umum 
digunakan: 

// definisi gorm.Model​
type Model struct {​
  ID        uint           `gorm:"primaryKey"`​
  CreatedAt time.Time​
  UpdatedAt time.Time​
  DeletedAt gorm.DeletedAt `gorm:"index"`​
} 

Kamu bisa langsung menyisipkan gorm.Model ke dalam 
struct milikmu agar field-field tersebut otomatis tersedia. Contoh 
cara penyisipan adalah 

type Author struct {​
    Name  string​
    Email string​
}​
​
type Blog struct {​
  ID      int​
  Author  Author `gorm:"embedded"`​
  Upvotes int32​
}​
// equals​
type Blog struct {​
    ID    int64​
    Name  string​
    Email string​
    Upvotes  int32​
} 

 
Cara diatas dapat diterapkan juga untuk gorm.Model 

cukup sisipkan “gorm.Model” dan itu akan langsung 
menambahkan field: ID, CreatedAt, UpdatedAt, DeletedAt dalam 
struct. Ini sangat berguna untuk menjaga konsistensi di antara 

​ ​                   
​ ​                   
​ ​ ​ 113 
 



 

berbagai model dan juga memanfaatkan aturan otomatis dari 
GORM. Penjelasan Field: 
1.​ ID: Penanda unik untuk tiap data (sebagai primary key). 
2.​ CreatedAt: Otomatis diisi dengan waktu saat data dibuat. 
3.​ UpdatedAt: Otomatis diperbarui dengan waktu saat data 

diubah. 
4.​ DeletedAt: Digunakan untuk soft delete, yaitu menandai data 

sebagai terhapus tanpa benar-benar menghapus dari 
database.

6.6.1. Has One 
Asosiasi Has One menetapkan hubungan satu-ke-satu 

dengan model lain, tetapi dengan semantik (dan konsekuensi) 
yang sedikit berbeda. Asosiasi ini menunjukkan bahwa setiap

instance dari model lain.

dan setiap pengguna hanya bisa memiliki satu kartu kredit.

c.​ Menimpa Foreign Key 

Untuk hubungan has one, kolom foreign key harus ada, dan 
entitas pemilik akan menyimpan primary key dari model 
yang dimilikinya ke dalam kolom ini. 

Nama kolom tersebut biasanya dihasilkan dari tipe model 
has one ditambah dengan primary key-nya, misalnya 
pada contoh di atas menjadi UserID. 

Ketika kamu memberikan kartu kredit ke pengguna, maka 
ID dari pengguna akan disimpan ke kolom UserID. 

Jika kamu ingin menggunakan kolom lain sebagai foreign 
key, kamu bisa mengubahnya dengan tag foreignKey, 
contohnya: 

type User struct {​
 gorm.Model​
 CreditCard CreditCard `gorm:"foreignKey:UserName"`​
 // use UserName as foreign key​
}​
​
type CreditCard struct {​
 gorm.Model​
 Number   string​
 UserName string​
}

7.1. Apa itu Postman 
Postman adalah sebuah platform yang digunakan untuk 

mengelola dan menguji API (Application Programming Interface). Alat 
ini banyak digunakan oleh developer karena memungkinkan pengujian 
berbagai permintaan HTTP secara langsung melalui antarmuka grafis 
yang user-friendly, dan juga tanpa perlu menulis kode secara manual. 

 
Melalui Postman, kamu bisa dengan mudah mencoba endpoint 

API, menambahkan parameter, menyusun headers, dan menganalisis 
respons dari server. Tak hanya untuk pengujian, Postman juga 
dilengkapi fitur untuk membuat dokumentasi, melakukan pengujian 
otomatis, serta mendukung kolaborasi dalam tim. 

 
Postman pertama kali dirilis pada tahun 2012 oleh Abhinav 

Asthana sebagai ekstensi di Google Chrome, dan sejak saat itu 
berkembang menjadi sebuah perusahaan teknologi global bernama 
Postman Inc. yang berbasis di San Francisco. Kini, Postman menjadi 
salah satu tools utama dalam proses pengembangan API modern. 

 
Postman tidak hanya berfungsi untuk mengirim permintaan ke 

API. Alat ini juga mendukung berbagai tahapan siklus pengembangan 
API: mulai dari desain, pengujian, simulasi, hingga monitoring. 
Fungsionalitasnya yang lengkap menjadikan Postman sebagai alat 
wajib bagi back-end developer maupun QA engineer. 

 
Fungsi Utama Postman: 

●​ Mengirim Permintaan API 
Mendukung permintaan HTTP seperti GET, POST, PUT, PATCH dan 
DELETE. Permintaan dapat disimpan dalam collection untuk 
digunakan kembali. 

●​ Pengujian Otomatis 
Menyediakan fitur scripting menggunakan JavaScript untuk 
memverifikasi response API secara otomatis. 

●​ Dokumentasi API 

​ ​                   
​ ​                   
​ ​ ​ 152 
 



 

Setiap permintaan yang dibuat bisa diubah menjadi 
dokumentasi interaktif yang mudah dibagikan ke tim 
pengembang atau klien. 

●​ Mock Server 
Membuat simulasi respons API untuk membantu pengembangan 
front-end meskipun back-end belum sepenuhnya selesai. 

●​ Monitoring 
Permintaan dapat dijadwalkan untuk dijalankan secara otomatis, 
memantau stabilitas API, dan mengirim notifikasi jika terjadi 
kegagalan. 

●​ Kolaborasi Tim 
Postman menyediakan workspace kolaboratif yang 
memungkinkan anggota tim bekerja secara sinkron terhadap 
koleksi, environment, dan pengujian API.

7.4. Environment dan Variabel 
Dalam pengujian API, kamu akan sering menggunakan alamat 

endpoint, token, atau ID yang berulang kali muncul di berbagai request. 
Daripada menyalin-tempel secara manual (yang rawan kesalahan), 

​ ​                   
​ ​                   
​ ​ ​ 160 
 



 

Postman menyediakan fitur Environment dan Variable untuk 
menyimpan nilai-nilai tersebut secara dinamis dan terorganisir.​  

 
Environment merupakan kumpulan dari variabel yang dapat 

digunakan pada request di Postman. Ketika melakukan pengujian 
otomatis, terkadang kita perlu menyimpan nilai pada sebuah variabel. 
Contohnya ketika melakukan request menambahkan catatan, kita akan 
mendapatkan id catatan tersebut dari server. Id tersebut perlu 
disimpan pada variabel agar dapat digunakan oleh request 
selanjutnya. 

 
Variabel tak hanya digunakan untuk kasus tersebut saja, 

melainkan dapat juga untuk menyimpan nilai token, auth-key, atau 
nilai lainnya yang dipakai selama proses uji. 

 
A.​ Konsep  Dasar 

1.​ Environment(Lingkungan) 
●​ Definisi: Set variabel yang spesifik untuk lingkungan 

tertentu (Development, Production, Staging). 
●​ Fungsi: 

○​ Memisahkan konfigurasi antar lingkungan (URL, 
kredensial, dll). 

○​ Memudahkan migrasi antar lingkungan tanpa 
mengubah manual tiap request. 

2.​ Variable (Variabel) 
●​ Jenis: 

○​ Global: Berlaku untuk semua request di 
workspace. 

○​ Environment: Hanya aktif di environment 
tertentu. 

○​ Local: Hanya berlaku untuk satu request. 
○​ Collection: Berlaku untuk seluruh request dalam 

koleksi. 
Dapat dikatakan environment dan variabel ini kita gunakan untuk 

mempermudah pekerjaaan kita, di mana kita tidak perlu menulis 
manual sesuatu yang berulang-ulang, juga dapat digunakan untuk 
menyimpan token yang kita perlukan nanti

7.5. Authorization (Bearer Token) 
Banyak API modern melindungi aksesnya dengan sistem 

authorization, agar hanya pengguna yang sah yang bisa 
menggunakan fitur tertentu, terutama yang berkaitan dengan

pembuatan, perubahan, atau penghapusan data. Salah satu metode

Bearer Token adalah string unik yang diberikan setelah kamu 

berhasil login atau mendaftar. Token ini harus dikirimkan di setiap 
request yang memerlukan otorisasi, biasanya lewat header: 

 
Authorization: Bearer <accessToken>

tutorial untuk menggunakan bearer token menggunakan API

metode POST yang ada di dropdown 

2.​ Masukkan URL endpoint (contoh: 
https://simple-books-api.click/api-clients)

text menjadi JSON, dan tuliskan struktur JSON berikut: 
{ 
    "clientName": "ButkemSCH",​
